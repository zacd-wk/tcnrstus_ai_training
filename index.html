// 11 · AI CO-PILOT

AI 協同開發理念 Co-Pilot Workflow

STEP 01

需求拆解

先精準定義業務需求與邊界條件，再讓 AI 協助列出情境、風險與驗收條件。

STEP 02

架構設計

與 AI 討論資料表設計、鎖策略與流程圖，比較多種方案後由工程師拍板。

STEP 03

協同開發

以 AI 產出樣板與單元測試草稿，工程師專注在核心商業邏輯與品質把關。

STEP 04

Code Review

AI 先行掃描潛在 Bug、N+1 查詢與資安疑慮，再由人工做最終審查。

STEP 05

SOP 沉澱

把有效的提示詞與流程固化為團隊 SOP，持續迭代整體產出品質。

// 12 · PHILOSOPHY

工程師的日常維運宣言 Engineering Philosophy

熱衷流程優化，把重複性工作SOP 化； 主動推動團隊內部統一開發規範，讓跨團隊溝通成本降到最低。

流程優化

持續檢視開發與維運流程，找出瓶頸並以自動化取代人工重複操作。

SOP 化

將排查、部署、壓測等重複性工作寫成可執行的標準流程，新人也能快速上手。

統一規範

推動命名、分支、Code Review 與 API 設計規範，讓程式碼風格一致、可維護。

降低溝通成本

以文件、規範與可觀測數據取代來回確認，縮短跨團隊協作的往返時間。

// 14 · FAQ

常見問答與合作模式 FAQ

  1. 先盤點痛點，用實際案例(如重複 Bug、溝通往返)說明價值。
  2. 與各團隊共同擬定最小可行規範，避免一次推太多。
  3. 以 Lint、CI 檢查與範本專案自動化落實，減少人工糾正。
  4. 定期回顧與修訂，讓規範隨團隊成長。

  1. 釐清目標：預期 QPS、P95/P99 延遲與錯誤率門檻。
  2. 以 k6 撰寫貼近真實流量的情境腳本。
  3. 逐步加壓，搭配 Datadog 觀察 CPU、連線池、慢查詢與鎖等待。
  4. 定位瓶頸、優化後重測，並把結果寫成報告與 SOP。

結合分散式鎖控制並發、資料庫 Transaction 確保原子性，並加入冪等鍵與對帳機制，達成最終一致性。

用 AI 協助需求拆解、方案比較、測試草稿與 Code Review 初篩，但關鍵決策與最終審查仍由工程師負責，並把有效流程沉澱為 SOP。

  • 後端 API / 資料表設計顧問
  • 效能壓測與瓶頸診斷
  • BigQuery 報表與 ETL 架構規劃
  • 團隊開發規範與 CI/CD 導入
